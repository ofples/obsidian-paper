# Getting started on desktop and Nomad

Obsidian Paper is one optional part of a desktop and Supernote Nomad workflow. You can keep using your existing Obsidian theme and add only the pieces you want. Transcripts is maintained separately and can recognize notebook files and add page links without Paper, Sidebar, or MD Reader.

For the current setup steps, notebook folders, plugin settings, and sync order, follow the [canonical Transcripts workflow guide](https://github.com/ofples/supernote-transcripts/blob/main/docs/workflow.md). This page gives the component map and decisions to make before following that guide; it avoids repeating steps that can change with plugin or device versions.

## What each part does

- **Obsidian Sync** carries Markdown notes, transcript files, and the Transcripts shared records between your desktop and Nomad vaults.
- **Supernote Cloud Sync** carries the original `.note` notebooks between the Nomad and your Supernote account. On desktop, the optional Supernote Cloud Sync Obsidian plugin can download those files into a local folder so Transcripts can read notebook pages there. Keep raw `.note` folders out of the Obsidian Sync path.
- **Supernote Transcripts** reads local notebook files, performs recognition when you choose to run it, writes transcript Markdown, and adds page links. It is an external companion; this repository does not bundle, download, install, or enable it.
- **Supernote Paper** changes Obsidian's appearance. Your desktop can keep its current theme while the Nomad uses Paper.
- **Supernote Sidebar** adds mobile navigation and reading controls. It can use standard Obsidian Markdown Preview when MD Reader is absent.
- **MD Reader** adds paginated Book reading. It is optional; ordinary Markdown, Transcripts page links, and continuous reading can work without it.

These are two different sync paths. Obsidian Sync is for vault Markdown and shared transcript records. Supernote Cloud Sync is for the original notebook files. Transcripts operates on a local `.note` file and uses a shared mirror identity to associate the corresponding source on each device; the actual source path and plugin run state stay local to that device.

## Start with the notebook workflow

1. Follow the [desktop setup](https://github.com/ofples/supernote-transcripts/blob/main/docs/workflow.md#set-up-the-desktop) to make a notebook available locally, exclude the raw notebook folder from Obsidian Sync, and configure Transcripts.
2. Follow the [Nomad setup](https://github.com/ofples/supernote-transcripts/blob/main/docs/workflow.md#set-up-obsidian-and-sync-on-nomad) to connect the same vault and shared mirror identity while retaining each device's own notebook path and configuration.
3. Check a transcript in standard Obsidian before adding optional presentation components. Follow the guide's sync order whenever notebook edits need to reach the other device.

## Read transcripts and jump to notebook pages

With Transcripts page links enabled, open a generated transcript in Obsidian Reading view or Live Preview and select a **p.N ↗** button. The transcript must contain the page metadata generated by Transcripts; Paper does not create page links. Source Mode shows the underlying metadata comments.

On desktop, a compatible enabled notebook viewer can open the corresponding page; otherwise Transcripts shows its read-only page preview. On Nomad, native Notes page navigation requires the separate Supernote login helper companion app. See the [page-link setup and limitations](https://github.com/ofples/supernote-transcripts/blob/main/PAGE_LINKS.md) before configuring it. Opening a page link does not start recognition.

MD Reader is optional for this workflow. If you prefer paginated Book reading, the compatible Reader fork can display the same Transcripts page links in its custom view; standard Reading view and Live Preview remain available without it.

## Keep the device settings separate

Use a separate Obsidian configuration folder/profile on the Nomad, such as `.obsidian-supernote`, while leaving the desktop on its existing `.obsidian` setup. In Obsidian Sync, disable the **Vault configuration** sync categories for the Nomad profile, but keep note and vault-file sync enabled. That lets the devices share Markdown while keeping theme and plugin settings, local notebook paths, credentials, and run state separate. Do not copy Transcripts' `data.json` or state files from one device to the other.

## Install only what you want

Download the named ZIP files from the [v0.5.11 prerelease page](https://github.com/ofples/obsidian-paper/releases/tag/v0.5.11) after it is published, then follow the self-contained [release installation guide](release-install.md). Use only the named release assets, not GitHub's generated source archives. Node.js is needed only when rebuilding from source; normal installation does not require a build.

The MD Reader bundled here is the [canonical Supernote fork](https://github.com/ofples/obsidian-md-reader). It and the upstream Reader use the same `md-reader` plugin ID, so install one at a time. Preserve an existing Reader `data.json`, which holds settings and reading state; do not replace it with the optional fresh-install defaults file.

Transcripts and its setup instructions live in the [separate repository](https://github.com/ofples/supernote-transcripts). For exact installation instructions and the recommended order for notebook transfer, recognition, and Obsidian Sync, use the [workflow guide](https://github.com/ofples/supernote-transcripts/blob/main/docs/workflow.md).
